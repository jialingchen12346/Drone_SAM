## 1. 修订合理性评估

### 1.1 v1 → v2 关键变更评价

| 变更 | 评价 | 理由 |
|------|------|------|
| 论文定位从"无人机搜救"改为"恶劣条件多模态分割" | **正确** | 数据集全是自动驾驶场景，强行套搜救概念会被审稿人质疑 |
| 创新点从 4 个缩减为 2+1 | **正确** | 应用类期刊更看重方法的深度和实验的充分性，而非创新点的数量 |
| 去掉 DINOv2 ViT-L，改用 ConvNeXt-Tiny | **正确** | DINOv2 增加 ~2-3GB 显存但边际收益不确定；ConvNeXt-Tiny 更务实 |
| 去掉边缘部署创新点 | **正确** | 无法在论文中验证的创新点没有说服力 |
| 基于 MM SAM-Adapter 框架而非从零搭建 | **正确** | 减少工程量 50%+，确保实验对比公平 |
| 时间从 10 周压缩到 9 周 | **合理** | 去掉部署优化阶段后的自然结果 |

### 1.2 保留内容评价

| 保留项 | 评价 | 说明 |
|--------|------|------|
| SAM2 Hiera-L 作为主编码器 | **合理** | 层级特征输出、强预训练、PEFT 友好 |
| RFB 思路（融入 HGSOAD） | **合理** | 多感受野增强小目标的思路有效，但整合进解码器更有创新性 |
| LoRA/Adapter 对比 | **合理** | 作为工程贡献和消融实验有价值 |

## 2. 创新点深度分析

### 2.1 CACAF 创新点分析

**创新性评分: 7/10**

| 维度 | 评价 |
|------|------|
| 新颖性 | **中高** — 模态质量评估 + 自适应融合的组合在多模态分割中较少见。注意力机制本身不新，但"条件感知"的角度新颖 |
| 技术深度 | **中** — MQA 分支是简单的 GAP + MLP，技术实现不复杂 |
| 实验可验证性 | **高** — 融合权重可以直接可视化，per-condition 分析可以量化验证 |
| 论文叙事性 | **高** — "恶劣条件下自适应选择更可靠的模态"故事性强，易于表达 |

**潜在风险**:
1. MQA 可能学到的是"模态判别"而非"质量评估" → 需要可视化验证
2. 如果数据集中恶劣条件比例不均衡，权重分布可能不明显 → DELIVER 有 5 种天气均衡分布，问题不大
3. 轻量级 MQA (GAP + MLP) 可能容量不足 → 可以增加到 3 层 MLP 或引入空间维度信息

**改进建议**:
- 考虑在 MQA 中加入空间维度信息（不只是全局 GAP），例如对高频和低频分量分别评估
- 可以引入"熵"作为辅助信号：高熵图像 = 低质量（雾天模糊图像的空间熵更低）

### 2.2 HGSOAD 创新点分析

**创新性评分: 6/10**

| 维度 | 评价 |
|------|------|
| 新颖性 | **中** — SAGU 本质上是 SE-like 通道注意力 + U-Net 跳跃连接，各部分已有先例 |
| 技术深度 | **中** — 架构清晰但缺乏突破性设计 |
| 实验可验证性 | **高** — 可通过小目标类别 IoU 直接验证 |
| 论文叙事性 | **中高** — "小目标感知"与应用场景吻合 |

**潜在风险**:
1. SAGU 与 SE-Net / CBAM 的差异不够大 → 审稿人可能认为缺乏新颖性
2. 门控机制在 U-Net 解码中是否真的对小目标有帮助 → 需要消融实验和特征可视化验证

**改进建议**:
- 可以考虑将 SAGU 升级为"空间+通道双注意力"（类似 CBAM 但更轻量）
- 增加一个"小目标聚焦损失"（如 area-weighted IoU loss），增强解码器对小目标的学习

## 3. 技术可行性分析

### 3.1 显存可行性

```
组件分析:
┌────────────────────────────────┬──────────┬────────────┐
│ 组件                           │ 参数量   │ 显存 (FP16) │
├────────────────────────────────┼──────────┼────────────┤
│ SAM2 Hiera-L (frozen, 仅前向)  │ ~300M    │ ~600MB     │
│ Adapter 参数                   │ ~2M      │ ~50MB      │
│ ConvNeXt-Tiny (可训练)         │ ~28M     │ ~2GB       │
│ CACAF × 4                      │ ~8M      │ ~1GB       │
│ HGSOAD                         │ ~10M     │ ~1GB       │
│ 特征图 + 激活值                │ -        │ ~6-8GB     │
├────────────────────────────────┼──────────┼────────────┤
│ 合计                           │ ~348M    │ ~12-14GB   │
│ (可训练: ~48M)                 │          │            │
└────────────────────────────────┴──────────┴────────────┘

4090 24GB 剩余 ~10GB 余量 → batch_size=2 可行
```

**评估: 可行 (4/5)**

注意事项:
- CACAF 中的 MultiheadAttention 在高分辨率层 (f1, stride=4) 序列长度很大，可能是显存瓶颈
- 建议: 在 stride=4 的层使用降采样后的注意力，或只在 stride ≥ 8 的层使用完整注意力
- 梯度检查点可进一步降低显存（SAM2 blocks 已支持）

### 3.2 CACAF 高分辨率层显存风险评估

```
FLM 数据集 (输入 800×800, crop 到 512×512):
  f1 (stride 4): 128 × 128 = 16,384 tokens
  f2 (stride 8): 64 × 64 = 4,096 tokens
  f3 (stride 16): 32 × 32 = 1,024 tokens
  f4 (stride 32): 16 × 16 = 256 tokens

MultiheadAttention 显存 ∝ L² (L=序列长度):
  f1: 16384² ≈ 2.7 亿 → 每层约 1GB（FP16）→ 风险!
  f2: 4096² ≈ 1700万 → 可接受
  f3: 1024² ≈ 100万 → 低
  f4: 256² ≈ 6.5万 → 极低

DELIVER 数据集 (输入 1024×1024):
  f1 (stride 4): 256 × 256 = 65,536 tokens → 严重不可行!
```

**重要修正建议**:
```
CACAF 策略调整:
  f1 (stride 4):  不使用交叉注意力，仅使用 MQA 权重加权融合
  f2 (stride 8):  使用降采样交叉注意力 (downsample 2x → 32×32 tokens)
  f3 (stride 16): 完整交叉注意力
  f4 (stride 32): 完整交叉注意力

或者:
  所有层都使用"高效注意力"变体:
  - 窗口注意力 (window_size=8)
  - 线性注意力 (kernel method)
  - 可变形注意力 (仅采样 k 个参考点)
```

**这是 v2 方案中需要额外关注的技术风险。建议在实现时优先处理。**

### 3.3 数据可行性

| 数据集 | 规模评估 | 风险 |
|--------|---------|------|
| FLM | 1,220 训练 / 280 测试 — **偏小** | 中（需要强数据增强） |
| DELIVER | ~4,000 训练 / ~2,000 验证 — 适中 | 低 |

**FLM 数据集小规模对策**:
1. 强数据增强: RandomCrop, RandomFlip, ColorJitter, RandomRotate
2. 预训练权重迁移: SAM2 + ConvNeXt 均有强预训练
3. 考虑从 DELIVER 预训练 → FLM 微调（跨域迁移）

### 3.4 代码复用可行性

| 复用项 | 来源 | 改造量 |
|--------|------|--------|
| 训练/测试框架 | MM SAM-Adapter | 低（直接使用） |
| 数据加载管道 | MM SAM-Adapter (FLM/DELIVER) | 低（已有实现） |
| SAM2 Hiera 编码器提取 | SAM2-UNeXT | 低（直接参考） |
| Adapter 包装 | SAM2-UNeXT/SAM2-UNet | 低（直接复用） |
| LoRA 包装 | SAMed | 中（需适配 SAM2 Hiera） |
| CACAF | 全新实现 | **高** |
| HGSOAD | 部分参考 SAM2-UNet 的 U-Net | 中 |
| 整体 Segmentor 组装 | MM SAM-Adapter | 中 |

**评估: 总改造量约 40% 新代码 + 60% 复用/改造**

## 4. 实验设计评估

### 4.1 对比实验充分性

| 评估维度 | 评分 | 说明 |
|----------|------|------|
| 对比方法数量 | 4/5 | 4 个对比方法（SegFormer, CMX, CMNeXt, MM SAM-Adapter）足够 |

### 4.2 消融实验充分性

| 评估维度 | 评分 | 说明 |
|----------|------|------|
| 模块消融 | 5/5 | 完整的 2×2 消融矩阵 |
| 内部消融 | 5/5 | CACAF 和 HGSOAD 各有独立内部消融 |
| PEFT 对比 | 4/5 | 5 种策略对比，足够 |
| 分析深度 | 5/5 | 权重可视化 + per-condition + 小目标分析 |

### 4.3 分析实验亮点评估

```
亮点实验排序:
1. CACAF 融合权重 per-condition 可视化   ← 最大亮点，直观展示"条件感知"
2. per-condition mIoU 分析              ← 展示恶劣条件下的优势
3. 小目标类别 IoU 分析                   ← 展示 HGSOAD 效果
4. PEFT 策略系统对比                     ← 工程贡献
5. 定性可视化 (分割结果对比)              ← 常规但必要
```

### 5.3 潜在审稿意见预判

| 可能的审稿意见 | 预案 |
|---------------|------|
| "CACAF 的 MQA 分支太简单" | 回应: 简单设计端到端有效，可视化结果证明学到了条件感知；增加复杂度不一定提升性能（提供消融） |
| "HGSOAD 的 SAGU 与 SE-Net/CBAM 区别？" | 回应: SE-Net 用于分类，SAGU 在分割解码路径中按尺度级别自适应门控，目的和位置不同 |

| "和 CMNeXt 的 Self-Query Hub 对比？" | 回应: CMNeXt 的 SQH 是多模态选择机制，我们的 CACAF 是条件感知融合，解决不同层次的问题 |
